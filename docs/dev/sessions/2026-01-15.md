## Technical Decisions

### 1. Quest System Architecture
**Decision:** Use DataAssets (UPrimaryDataAsset) instead of DataRegistry  
**Rationale:**
- `UQuestDefinition` inherits from `UPrimaryDataAsset`
- DataAssets work with AssetManager for async loading
- DataRegistry requires USTRUCT, incompatible with UCLASS
- Existing implementation already uses DataAssets (`DA_TestQuest_*.uasset`)

### 2. Inventory-Weapon Integration
**Decision:** Inventory owns items, WeaponComponent spawns runtime actors  
**Pattern:**
- Items stored in `InventoryComponent` (data)
- `EquipWeaponItem()` → `WeaponComponent::AddWeaponClass()` (runtime spawn)
- `UnequipWeaponItem()` → `WeaponComponent::RemoveCurrentWeapon()` (despawn)
- `EquippedWeaponItem` tracks equipped state

### 3. Ammo Bridge Layer
**Decision:** Ammo stored in inventory, bridged to WeaponComponent  
**Implementation:**
- `GetReserveAmmo(AmmoType)` - Query inventory for ammo items
- `ConsumeReserveAmmo(AmmoType, Amount)` - Remove from inventory
- `AddReserveAmmo(AmmoType, Amount)` - Add to inventory
- `AmmoTypeToItem` TMap for type→ItemDefinition mapping
