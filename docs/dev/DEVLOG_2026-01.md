## 2026-01-14 - Late Evening Session (23:00 - 23:20)
### Focus: T-pose Fix, Sprint/Crouch Input, GASP Research

#### What was done?
- **T-pose Bug Investigation & Fix:**
  - Root cause: `StartingWeaponClass` in WeaponComponent spawns weapon at BeginPlay
  - Weapon calls `OnWeaponActivated()` which sets `ThirdPersonAnimInstanceClass`
  - If weapon has no AnimBP configured → mesh gets null AnimClass → T-pose
  - **Solution:** Defensive fallback in `OnWeaponActivated()`:
    - Check if `WeaponAnimClass` is valid before setting
    - If null, fallback to `UnarmedAnimInstanceClass` and log warning
  - Added defensive null checks in `BaseWeapon::BeginPlay` for `OwnerActor` and `WeaponOwner`

- **Sprint Input System:**
  - Implemented hold-to-sprint with Enhanced Input bindings
  - `Started` + `Triggered` → `DoStartSprint()`
  - `Completed` + `Canceled` → `DoEndSprint()`
  - Verified working in PIE

- **Crouch Input System:**
  - Added `CrouchAction` UPROPERTY to BasePlayerCharacter
  - Implemented `DoStartCrouch()` / `DoEndCrouch()` handlers
  - Enabled `bCanCrouch` in CharacterMovement constructor
  - Same binding pattern as sprint (Started/Triggered/Completed/Canceled)
  - Created `IA_Crouch` input action

- **GASP Research & Documentation:**
  - Researched Epic's Game Animation Sample Project (Motion Matching)
  - Key systems: Pose Search, Choosers, Linked Anim Graph
  - Created `animation_guide.md` with integration roadmap:
    - Phase 0: Baseline + Instrumentation
    - Phase 1: Adopt GASP Concepts Without Migration
    - Phase 2: Motion Matching (Smallest Working Slice)
    - Phase 3: Choosers (Context-Driven DB Selection)
    - Phase 4: Weapon Overlays + Action System
    - Phase 5: Retargeting New Characters

#### What did we learn?
- T-pose often caused by null/incompatible AnimClass being set
- SetAnimInstanceClass(null) or invalid class → mesh uses reference pose
- Epic GASP uses Motion Matching + Choosers for responsive locomotion
- Crouch requires `bCanCrouch = true` in CharacterMovement
- Enhanced Input `Triggered` event fires continuously while held

#### Problems & Solutions
- **Problem:** T-pose when StartingWeaponClass configured
  - **Cause:** Weapon's ThirdPersonAnimInstanceClass was null
  - **Solution:** Fallback to UnarmedAnimInstanceClass if weapon AnimBP missing

- **Problem:** Crouch input triggers but nothing visible happens
  - **Cause:** No crouch animation in current ABP
  - **Status:** Deferred to GASP integration (Phase 2+)
